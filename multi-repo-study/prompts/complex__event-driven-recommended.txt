Task: add the ability to remove a single line item from an order before it's paid.

Requirements:
1. Add a domain event `OrderItemRemovedDomainEvent` in `src/Ordering.Domain/Events/`,
   carrying at least the order's id and the removed item's `ProductId`, following the
   existing domain event classes' shape and constructor style in that folder.
2. Add a method `Order.RemoveOrderItem(int productId)` to
   `src/Ordering.Domain/AggregatesModel/OrderAggregate/Order.cs`:
   - Throws `OrderingDomainException` if `OrderStatus` is `Paid`, `Shipped`, or
     `Cancelled` (an order in any of those states can't have its items changed).
   - Throws `OrderingDomainException` if no item with that `productId` exists on the
     order.
   - Throws `OrderingDomainException` if the order only has one item (an order
     can't be left with zero items via this method — cancel the whole order for
     that case instead).
   - Otherwise removes the matching `OrderItem` from the order's items and raises
     `OrderItemRemovedDomainEvent`.
3. Add `RemoveOrderItemCommand(int OrderNumber, int ProductId) : IRequest<bool>` and
   `RemoveOrderItemCommandHandler` in `src/Ordering.API/Application/Commands/`,
   following the same shape as `CancelOrderCommand`/`CancelOrderCommandHandler`:
   load the order via `IOrderRepository`, return `false` if not found, call
   `Order.RemoveOrderItem`, persist via `_orderRepository.UnitOfWork.SaveEntitiesAsync`.
4. Add `RemoveOrderItemCommandValidator` in
   `src/Ordering.API/Application/Validations/`, following
   `CancelOrderCommandValidator`'s shape — validate both `OrderNumber` and
   `ProductId` are present/non-empty.
5. Add a domain event handler for `OrderItemRemovedDomainEvent` in
   `src/Ordering.API/Application/DomainEventHandlers/` that at minimum logs the
   removal (matching the logging style of the existing handlers in that folder,
   e.g. via `ILogger`) — it does not need to publish an integration event.
6. Add tests to `tests/Ordering.UnitTests/`:
   - In `Domain/OrderAggregateTest.cs` (or similar): removing an existing item
     succeeds and raises the domain event; removing a nonexistent product throws;
     removing the last remaining item throws; removing from a `Paid` order throws.
   - In `Application/` (new file, following `NewOrderCommandHandlerTest.cs`'s
     NSubstitute-mocking style): the command handler returns `false` for a
     nonexistent order, and calls `Order.RemoveOrderItem` + saves for a valid one.

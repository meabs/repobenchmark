You're working in this repo: a Spring Framework (not Spring Boot) PetClinic
application — plain XML `ApplicationContext` configuration, JSP views, a 3-layer
architecture (web → service → repository), built with Maven.

Task: add the ability to mark a Pet as deceased.

Requirements:
1. Add an `isDeceased` boolean field to `Pet`, default `false`.
2. The field must be correctly read and written under all three repository
   profiles this codebase supports for `PetRepository` (find them yourself — the
   codebase has more than one implementation of this interface, and they are not
   equally affected by this kind of change). Add the column to the H2 schema used
   by the test suite.
3. Add a service-layer method to mark a pet deceased (and, separately, to undo
   that) via `ClinicService`/`ClinicServiceImpl`, delegating to the existing
   `PetRepository` interface — not to a specific implementation class.
4. Add a new controller endpoint (in the existing pet-related controller, following
   its existing conventions) that lets a user mark a pet as deceased from the pet's
   detail page, and a way to undo it. Use the same ownership rules already enforced
   elsewhere for editing a pet (only reachable from the owning owner's pages — don't
   invent a separate authorization mechanism).
5. On the owner detail page, visually distinguish deceased pets from active ones
   (e.g. a label or styling difference in the JSP), and the pet listing there
   should still show deceased pets (don't hide them) but clearly marked.
6. Add tests: a service-level test (in the shared base test class, so it runs
   against all three repository profiles) that marks a pet deceased and reloads it
   to confirm persistence, and a controller-level (`MockMvc`) test that hits the new
   endpoint(s) and asserts the expected redirect/response.

Definition of done — and how to check each one, not just assert it:
- All three repository-implementation test classes pass with your new
  shared-base-class test included (not just one profile).
- The new controller endpoint(s) actually work: run the full test suite (`mvn
  test`), including your new `MockMvc` test, and confirm it's green — don't infer
  correctness from the code looking right.
- The JSP change is real: the JSP template must reference the new field's state
  (e.g. via a conditional block), not just have the backend support it invisibly.
- No hand-written SQL added outside the JDBC implementation's existing SQL-string
  style — match its conventions, don't introduce a new persistence approach.

Work through this yourself — explore the codebase as needed to find the relevant

Task: close a validation gap on `OrderItem`.

Context: `OrderItem`'s constructor already rejects an item whose `Discount` exceeds
its total (`unitPrice * units < discount` throws `OrderingDomainException`). But
`OrderItem.SetNewDiscount(decimal discount)` — called later, e.g. when
`Order.AddOrderItem` bumps an existing line's discount — only rejects a negative
discount. It does not re-check the discount against that item's total, so an
existing order item can end up with a discount larger than its own total via this
path even though the same thing is blocked at construction time.

Requirements:
1. In `src/Ordering.Domain/AggregatesModel/OrderAggregate/OrderItem.cs`, add a check
   to `SetNewDiscount` so that it also throws `OrderingDomainException` (matching
   the message style already used in the constructor) when the new discount would
   exceed `UnitPrice * Units`.
2. Keep the existing negative-discount check working unchanged.
3. Add a test (in `tests/Ordering.UnitTests/Domain/OrderAggregateTest.cs`, or a new
   file in that same folder if you prefer) that verifies: (a) `SetNewDiscount` still
   rejects a negative discount, and (b) `SetNewDiscount` now rejects a discount
   greater than the item's total.
4. No API, command, or frontend changes — this is a Domain-layer-only fix.
